## 数据与协议兼容

- 应用与扩展版本均为 0.1.1，应一起更新并重新加载 VS Code 窗口。
- 本机接入协议保持 v1；增加可选的 brokerId 字段和失效请求的 410 响应。新版扩展能使用旧描述文件的令牌识别服务实例变化。
- 组织文件升级为 v2；首次读取 v1 文件前创建 `organization.before-migration-v1.json`，再写入迁移结果。导入 v1 时也保留位置 ID、环境 ID、路径、名称与工作集关系。
- v1 组织记录内的存在状态、分支和 HEAD 不迁移为实时事实。独立发现缓存仍可使用；无缓存时需重新扫描。
- 扫描失效采用结果隔离，已经启动的只读扫描可能运行到原来的超时，结果不会回写。

## 验证范围

`npm test` 共 28 项通过。回执故障注入使用实际扩展实现和真实 HTTP，但 VS Code API 为模拟；不能将它描述为真实窗口验证。另有独立的官方 VS Code 稳定版桌面端到端流程，见[验证记录](validation.md)。

修复过程中，去掉祖先推断后，真实多根测试暴露出 VS Code Git API 没有提供父仓库的问题；随后增加了只读 `git rev-parse --show-toplevel` 查询及回归测试。本机查询失败时只关联精确工作区目录，不能恢复路径猜测。

macOS 真机、真实外部 SSH 主机、签名与公证仍不在已验证范围内。远端不能取得 Git 根证据时，只展示精确目录和真实会话，不把子目录窗口算入推测的父 checkout。
